# Characteristics of Software

## Definition

Software is a collection of **programs, data, documentation, and associated procedures** that instruct a computer to perform specific tasks.

Unlike physical products, software has unique characteristics because it is **intangible** and developed through engineering rather than manufacturing.

Understanding these characteristics helps explain why software development differs from other engineering disciplines.

---

# Why Study the Characteristics of Software?

Knowing these characteristics helps us:

* Understand why software projects are difficult to manage.
* Appreciate the importance of Software Engineering.
* Design better software systems.
* Improve software quality and maintainability.
* Answer common interview and exam questions.

---

# Major Characteristics of Software

There are **nine** widely accepted characteristics that distinguish software from physical products.

---

# 1. Software is Intangible

Software cannot be physically touched or measured like hardware.

It exists as:

* Source code
* Executable programs
* Digital files
* Documentation
* Databases

Unlike a laptop or a mobile phone, software has no physical form.

### Example

* Windows Operating System
* Google Chrome
* WhatsApp
* VS Code

You can install or copy them, but you cannot physically hold the software itself.

---

# 2. Software is Developed, Not Manufactured

This is one of the most important interview questions.

Hardware is manufactured repeatedly after a design is completed.

Software is engineered once by developers through activities such as:

* Requirement analysis
* Design
* Coding
* Testing
* Deployment

Once developed, making additional copies costs almost nothing.

### Hardware Example

Design one laptop → Manufacture one million laptops.

Manufacturing cost remains significant for every unit.

### Software Example

Develop Microsoft Word once → Downloaded millions of times.

The development is expensive, but each additional copy has a negligible cost.

---

# 3. Software Does Not Wear Out

Physical products deteriorate over time because of friction, corrosion, or material fatigue.

Software does **not** physically wear out.

However, software quality can degrade due to:

* Frequent modifications
* Poor maintenance
* Technical debt
* Increasing complexity

This phenomenon is often called **software deterioration** rather than physical wear.

### Example

A calculator application written ten years ago may still function correctly if the environment remains compatible.

---

# 4. Software is Highly Complex

Modern software systems may contain:

* Millions of lines of code
* Thousands of modules
* Hundreds of developers

Managing such complexity requires:

* Modular design
* Documentation
* Version control
* Testing
* Code reviews

### Example

Large systems such as banking platforms, operating systems, and cloud services involve numerous interconnected components.

---

# 5. Software is Easy to Modify

Software can be updated after deployment.

Common modifications include:

* Bug fixes
* New features
* Security patches
* Performance improvements
* UI enhancements

Unlike hardware, modifications usually do not require rebuilding a physical product.

### Example

Your smartphone apps receive regular updates through the app store.

---

# 6. Software Requires Continuous Maintenance

Maintenance often consumes the majority of a software system's lifetime cost.

Typical maintenance activities include:

* Corrective Maintenance (bug fixes)
* Adaptive Maintenance (environment changes)
* Perfective Maintenance (performance or usability improvements)
* Preventive Maintenance (future-proofing and code cleanup)

### Example

Web browsers receive frequent updates to fix security vulnerabilities and improve compatibility.

---

# 7. Software is Custom-Built (Historically)

Traditionally, software was developed specifically for a particular customer or organization.

Examples:

* Hospital Management System
* College ERP
* Banking Software

Today, this characteristic has evolved.

Many systems are built using:

* Reusable libraries
* Frameworks
* Open-source packages
* APIs
* Cloud services

Modern software development emphasizes **reuse** rather than building everything from scratch.

---

# 8. Software Evolves Continuously

Software is rarely "finished."

User needs change over time.

Technology evolves.

Security threats emerge.

Businesses introduce new requirements.

As a result, software undergoes continuous evolution.

### Example

Social media applications regularly add:

* New features
* Better recommendations
* Security improvements
* Performance optimizations

---

# 9. Software is Invisible

Unlike buildings or machines, software has no physical structure that can be directly observed.

Developers rely on models and documentation to understand software.

Examples include:

* UML diagrams
* Flowcharts
* Architecture diagrams
* ER diagrams

These visual representations make complex systems easier to understand.

---

# Software vs Hardware

| Feature      | Software                          | Hardware                       |
| ------------ | --------------------------------- | ------------------------------ |
| Nature       | Intangible                        | Physical                       |
| Creation     | Developed                         | Manufactured                   |
| Wear         | Does not physically wear out      | Wears out over time            |
| Copy Cost    | Almost zero                       | Manufacturing cost per unit    |
| Maintenance  | Updates and patches               | Physical repair or replacement |
| Modification | Easy                              | Often expensive or impossible  |
| Reuse        | High through libraries/frameworks | Limited by physical design     |

# Real-World Example

## Mobile Banking Application

During development:

* Requirements are gathered.
* Developers design the system.
* Code is written.
* Testing is performed.

After release:

* Bugs are fixed.
* New payment methods are added.
* Security patches are deployed.
* Performance is improved.

Even though millions of users download the app, the software itself does not wear out. It evolves through updates.

---

# Common Misconceptions

### ❌ Software never changes.

**Reality:** Most software changes continuously throughout its lifecycle.

---

### ❌ Software becomes old like hardware.

**Reality:** Software does not physically age. It becomes outdated when requirements, platforms, or technologies change.

---

### ❌ Copying software is expensive.

**Reality:** The expensive part is development. Once created, software can be copied at minimal cost.

---

# Interview Questions

## Why is software said to be developed and not manufactured?

Software is created through engineering activities such as analysis, design, coding, and testing. Once developed, additional copies can be distributed at almost no cost, unlike hardware that must be manufactured for each unit.

---

## Does software wear out?

No. Software does not physically wear out. However, frequent modifications, poor maintenance, and changing environments can reduce its quality and maintainability.

---

## Why is software maintenance important?

Software must adapt to new requirements, fix defects, improve performance, address security vulnerabilities, and remain compatible with evolving technologies.

---

## Why is software considered invisible?

Because software has no physical structure. Developers use diagrams, documentation, and models to visualize and understand it.


---

# Summary

Software possesses unique characteristics that distinguish it from physical products. It is intangible, engineered rather than manufactured, highly complex, continuously evolving, and requires regular maintenance. These characteristics explain why software projects demand structured engineering practices instead of relying solely on programming skills.

---

# Key Takeaways

* Software is **intangible** and exists in digital form.
* It is **developed**, not manufactured.
* It **does not physically wear out**, but it can deteriorate due to poor maintenance and continuous changes.
* Modern software emphasizes **reuse**, **modularity**, and **continuous evolution**.
* Understanding these characteristics provides the foundation for studying SDLC, software design, testing, maintenance, and architecture.
